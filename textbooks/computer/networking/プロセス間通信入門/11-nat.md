# 11. NAT

## 11.1 グローバル IP を持つのはどのルーターか

普通は、家に置いてあるルーター（Wi-Fi ルーターや、光回線の終端装置と一体になった機器）である。ISP から借りている機器のこともあるが、置き場所は家の中である。グローバル IP は、ISP がそのルーターのインターネット側（WAN 側）に割り当てる。

例外もある。日本の IPv6 接続サービス（v6プラス、transix などの IPv4 over IPv6）や携帯回線では、ISP 側の設備が多くの利用者で1つのグローバル IP を共有する方式（CGNAT など）がよく使われる。この場合、スキャンが届くのは ISP の設備で、家のルーターはグローバル IP を直接持っていない。

## 11.2 NAT とは

NAT（Network Address Translation）は、家の中のプライベート IP と、外のグローバル IP を付け替える仕組みである。家の中の機器はすべて、外からは1つのグローバル IP に見える。

```
PC 192.168.1.10:51000  →  ルーターが書き換え  →  203.0.113.5:40001 → Web サーバー
```

- **外に出るとき**：ルーターは送信元の `192.168.1.10:51000` を、自分のグローバル IP とポート `203.0.113.5:40001` に書き換える。その対応を NAT 変換テーブルに記録する。
- **返事が来たとき**：宛先 `203.0.113.5:40001` を NAT 変換テーブルで引いて `192.168.1.10:51000` に戻し、PC に届ける。
- **外から突然来たとき**：スキャンの SYN のように、外から始まった接続には NAT 変換テーブルに対応する行がない。ルーターはどの機器に渡せばよいか分からないので、捨てる。これが「NAT がスキャンを通さない」理由である。

NAT 変換テーブルは、カーネルが4つの組で確立済み接続テーブルを引く（[8章](08-tcp-loopback-and-port.md)）のと同じ考え方で、ルーターの中で接続を探している。

NAT の本来の目的は、足りない IPv4 アドレスを節約することである。外からの接続を防ぐ効果は副産物なので、ファイアウォール（[12章](12-firewall.md)）の代わりとして頼り切るものではない。

## 11.3 DNS の CNAME との違い

NAT は「別の名前に付け替える」という点で DNS の CNAME に似て見えるが、仕組みはかなり違う。

| | DNS の CNAME | NAT |
|---|---|---|
| 何をするか | 名前を別の名前に言い換える（別名） | パケットのヘッダにある IP とポートを書き換える |
| いつ働くか | 接続の前に、クライアントが名前を引くとき1回だけ | 接続中のすべてのパケットに対して、行きも帰りも |
| 状態を持つか | 持たない（固定の対応） | 持つ（接続ごとに変換テーブルの行を作って消す） |
| 対応の形 | 1つの名前 → 1つの名前 | 多数のプライベート IP → 1つのグローバル IP（ポートで区別する） |

一番大きな違いは、CNAME はデータそのものには触れず、NAT は流れている1つ1つのパケットを書き換えている点である。

## 11.4 たとえ：代表電話と内線

NAT は、会社の代表電話と内線にたとえると分かりやすい。

| 電話 | NAT |
|---|---|
| 会社の代表番号 | グローバル IP |
| 社員の内線 | プライベート IP |
| 交換台 | ルーター |

- 外からは、会社の代表番号しか見えない。
- 社員が外に電話をかけると、相手には代表番号が表示される。
- 折り返しの電話は、交換台が「さっきかけた人」を覚えているので、その内線につないでくれる。
- 内線を指定せずに外からかかってきた知らない電話は、つなぐ先が分からないので取り次がれない。これがスキャンを通さない理由である。
- ポートフォワーディングは、「この番号にかかってきたら、必ずこの内線につなぐ」という固定の取り次ぎ設定にあたる。

## 11.5 送信元 NAT と宛先 NAT

外と中を変換するのは、どちらの向きも NAT である。書き換える向きによって呼び名が分かれる。

| 呼び名 | 書き換えるもの | 使われる場面 |
|---|---|---|
| 送信元 NAT（SNAT。Linux ではマスカレードとも呼ぶ） | 出ていくパケットの送信元（プライベート → グローバル） | 中から外への普段の通信。変換テーブルの行は自動で作られる |
| 宛先 NAT（DNAT） | 入ってくるパケットの宛先（グローバル → プライベート） | ポートフォワーディング。変換テーブルの行は人が固定で書く |

どちらの場合も、返りのパケットは逆向きに書き換えて戻す。

家庭用ルーターの NAT は、IP だけでなくポートも書き換える。そのため、厳密には NAPT（Network Address Port Translation）、または PAT と呼ぶ。一般にはまとめて「NAT」と呼ばれることがほとんどである。

## 11.6 ポートフォワーディング

ポートフォワーディングは、ルーターに「外のこのポートに来た接続は、中のこの機器のこのポートに渡す」と固定で設定しておく機能である。外から始まる接続を、中の機器に届けるための手段である。

| 外（ルーターのグローバル IP） | 渡す先（中の機器） |
|---|---|
| `203.0.113.5:8080` | `192.168.1.10:80` |

外から `203.0.113.5:8080` に SYN が届くと、ルーターは宛先を `192.168.1.10:80` に書き換えて、中の機器に渡す。返事のパケットは逆向きに書き換えて、外に返す。

**よくある使い道**

- 家で動かしているサーバー（Web、ゲーム、NAS など）を外から使えるようにする。
- 防犯カメラを外から見られるようにする。

**注意点**

- 開けたポートは、外からのスキャンで見つかる。渡す先のソフトウェアに脆弱性があれば、そこが入口になる（[10章](10-port-scan.md)）。
- 渡す先の機器は、プライベート IP が変わらないように固定しておく必要がある。DHCP で IP が変わると、別の機器に転送されてしまう。
- CGNAT（11.1）の回線では、家のルーターがグローバル IP を持たないので、家のルーターで設定しても外からは届かない。

家の機器を外から使うだけなら、ポートを開けずに済む方法もよく使われている。Tailscale のような VPN や、Cloudflare Tunnel のように中から外へ接続を張る方式である。これらは「こちらから先に接続を始める」仕組み（11.8）を応用したもので、外からのスキャンには何も見えない。

### 1対1になるか

外のポート1つに対しては、渡す先は1つだけである。逆向きは1対1でなくてもかまわない。

| パターン | 可否 | 例 |
|---|---|---|
| 外のポート1つ → 中の1か所 | できる（基本形） | `:8080` → `192.168.1.10:80` |
| 外のポート1つ → 中の複数か所 | できない | 届いた SYN をどこに渡すか決められない（振り分けが必要ならロードバランサーを使う） |
| 外の複数ポート → 中の同じ1か所 | できる | `:8080` と `:8081` → どちらも `192.168.1.10:80` |
| 外の複数ポート → 中の別々の機器 | できる | `:8080` → `.10:80`、`:8081` → `.11:80` |
| ポートの範囲ごと | 多くのルーターでできる | `:5000-5010` → `.10:5000-5010` |

似た名前の「1:1 NAT」は別の機能である。ポート単位ではなく IP アドレス単位で、グローバル IP 1つを中の機器1台に丸ごと対応させる。グローバル IP を複数持っている場合に使う機能で、主に企業やクラウドで使われる。家庭用ルーターの DMZ 設定は、これに近い挙動である。

## 11.7 なぜ「ポート」フォワーディングと呼ぶか

正確には、対応は `(グローバル IP, ポート) → (プライベート IP, ポート)` であり、IP とポートの両方を使う。それでも「ポート」フォワーディングと呼ぶのは、家庭では外側の IP が1つしかないからである。

- **外側**：ルーターのグローバル IP は1つで、どの設定でも同じである。そのため、外から来た接続をどの機器に渡すかは、宛先ポートで見分けるしかない。
- **中側**：渡す先は、機器を指すプライベート IP と、その機器の中のソケットを指すポートの組である。

```
外: 203.0.113.5 : 8080   ← IP は固定、ポートで見分ける
        ↓
中: 192.168.1.10 : 80    ← IP で機器を決め、ポートでソケットを決める
```

1:1 NAT は、まさに IP 単位で対応させる方式である。グローバル IP を複数持っていれば IP ごとに1台へ渡せるので、ポートで見分ける必要がない。

## 11.8 接続は必ず中から始まる

NAT の後ろにいる限り、基本的にはこちらから先に接続を始めている。外から届いているように見えるものも、実はこちらが先に張った接続の上に乗っている。

- **プッシュ通知やチャットの着信**：端末が、Apple や Google の通知サーバー、あるいはチャットのサーバーに、前もって中から接続を張りっぱなしにしている。サーバーは、新しいメッセージをその接続を通して送ってくる。外から新しく接続されているわけではない。
- **キープアライブ**：何も送らない時間が続くと、ルーターは接続追跡テーブル（[12章](12-firewall.md)）の行を時間切れで消してしまう。そうなると、届くはずのデータも捨てられる。そのため、張りっぱなしの接続では、定期的に小さなパケットを送って行を保っている。
- **UDP**：UDP には接続という概念がないが、ルーターは「中から送った宛先からの返事」を同じようにテーブルで追跡している。

ビデオ通話や P2P のように、相手とつながる必要がある通信は、次の方法を使う。

| 方法 | 仕組み |
|---|---|
| ホールパンチング | 両方が同時に相手に向けて先にパケットを送る。それぞれのルーターに「中から始めた接続」として行ができるので、お互いのパケットが通るようになる。相手のグローバル IP とポートを知るために STUN というサーバーを使う。UDP でよく使われる |
| 中継（TURN） | ホールパンチングに失敗した場合、両方が外のサーバーに中から接続し、そのサーバーがデータを中継する |
| UPnP | アプリがルーターに頼んで、ポートフォワーディングを自動で設定する。便利だが、知らないうちに穴が開くので、セキュリティの面では注意が必要である |

### 例外：外から届く場合

こちらから始めなくても外から届くのは、次の場合である。

- ポートフォワーディングや UPnP で、ポートを開けている。
- ルーターの DMZ 設定で、特定の機器への通信をすべて通している。
- IPv6 で、ルーターのファイアウォールが外からの接続を許可している。
