# 4. 共有メモリ

## 4.1 仕組み

共有メモリは、カーネルに頼んで、同じ物理メモリのページを2つのプロセスのアドレス空間の両方に割り当ててもらう仕組みである。ソケットのような2回コピーをなくせる。

## 4.2 作り方（POSIX）

```c
fd = shm_open("/myshm", O_CREAT | O_RDWR, 0600);  // 名前付きの共有メモリを作る
ftruncate(fd, 4096);                               // サイズを決める
p = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);  // 自分のアドレス空間に割り当てる
```

相手のプロセスも同じ名前で `shm_open` と `mmap` をすると、両方の `p` が同じ物理メモリを指す。仮想アドレスの値はプロセスごとに違ってもかまわない。

## 4.3 特徴

- カーネルが関わるのは最初の設定のときだけ。その後は、片方が `p[0] = 1` と書けば、もう片方からすぐに見える。コピーもシステムコールもない。
- そのかわり、同時に書き込まないようにする排他制御や、書き終わったことを相手に知らせる仕組みを自分で用意する必要がある（[5章](05-locking.md)）。

## 4.4 ほかの方法

- System V の `shmget` / `shmat`
- 通常のファイルを `MAP_SHARED` で `mmap` する

PostgreSQL の shared_buffers は、共有メモリを使った代表例である。
