# 5. 排他制御とロック

## 5.1 ロックの正体

ロックの正体は、多くの場合メモリ上の小さな値（フラグ）である。0 なら空き、1 なら使用中のように表す。ただし重要なのは、フラグそのものより次の2点である。

- **確認と書き込みを一度に行う**：「0 か確認してから 1 を書く」を2つの操作に分けると、その間に別のプロセスも 0 を見て、両方がロックを取れてしまう。そこで compare-and-swap のような CPU のアトミック命令で、分割できない1回の操作として行う。
- **待ち方**：ロックが使用中のとき、値を繰り返し確認し続けるのがスピンロック、カーネルに頼んで眠らせてもらうのが futex である。

## 5.2 共有メモリでの排他制御

どの方法も、ロック用のオブジェクトを共有メモリの中に置き、両方のプロセスから使う。

### プロセス間で共有できる mutex

pthread の mutex に `PTHREAD_PROCESS_SHARED` 属性を付けて、共有メモリの中に置く。

```c
pthread_mutexattr_t a;
pthread_mutexattr_init(&a);
pthread_mutexattr_setpshared(&a, PTHREAD_PROCESS_SHARED);
pthread_mutex_init(&shm->lock, &a);   // shm は共有メモリ上の構造体

pthread_mutex_lock(&shm->lock);
shm->value++;                          // ここは同時に1プロセスだけが実行できる
pthread_mutex_unlock(&shm->lock);
```

ロックを持ったままプロセスが落ちて全体が止まるのを防ぐには、robust mutex（`PTHREAD_MUTEX_ROBUST`）を使う。

### セマフォ

名前付きの `sem_open`、または共有メモリの中に置く `sem_init(pshared=1)` を使う。「データが何件たまったか」を数えたり、相手に通知したりするのにも使える。macOS では `sem_init` は使えない。

### アトミック変数と futex

アトミック命令でロックを取り、待つ必要があるときだけ futex でスリープする。mutex の内部もこの仕組みで作られている。

### ロックを使わない構造

書き手と読み手が1人ずつなら、アトミックな読み書きだけでリングバッファを作れる。速度を優先する場合に使う。

## 5.3 ファイルを使うロック

| 方法 | 状態の持ち方 | 異常終了したとき |
|---|---|---|
| `flock` / `fcntl` のファイルロック | カーネルが管理する（ファイルの中身ではない） | 自動で解除される |
| ロックファイル（`xxx.lock`、pid ファイル） | ファイルが存在すれば使用中という取り決め | ファイルが残ることがある |

ロックファイルが残る問題は、[1章](01-unix-domain-socket.md)の古いソケットファイルが残る問題と同じ構造である。
