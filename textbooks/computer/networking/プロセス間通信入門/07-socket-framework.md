# 7. ソケットの共通の枠組み

## 7.1 Unix ソケットと TCP ソケットは同じ種類のオブジェクト

Unix ソケットも TCP ソケットも、カーネルの中にある同じ種類のオブジェクト（ソケット）である。違うのは種類（アドレスファミリー）だけだ。

| | Unix ソケット | TCP ソケット |
|---|---|---|
| 作り方 | `socket(AF_UNIX, SOCK_STREAM, 0)` | `socket(AF_INET, SOCK_STREAM, 0)` |
| 名前の付け方 | ファイルパス | IP アドレス + ポート |
| 中の処理 | 相手のバッファに直接つなぐ | TCP/IP の処理を通る |

- **共通の部分**：どちらも fd で扱え、`bind`、`listen`、`accept`、`connect`、`read`、`write` という同じ関数で使える。プログラムから見た使い方はほぼ同じである。待ち受けソケットと接続済みソケットの関係も同じである（[2章](02-connection.md)）。
- **違う部分**：名前の付け方と、カーネルの中での処理である。`socket()` の第1引数で、中で使われる実装が切り替わる。Linux では、ソケットが持つ処理表（関数ポインタの表）が TCP 用か Unix 用かで変わる。

同じ形のコンセントに、中の配線が違うものがつながっているイメージである。使う側から見た形は同じでも、つながっている先が違う。

## 7.2 「ソケット」という言葉の曖昧さ

ネットワークの文献では、「ソケット」が別の意味で使われることがある。TCP の仕様（RFC 793）では、「IP アドレスとポートの組」を socket と呼んでいる。文章を読むときは、カーネルのオブジェクトを指しているのか、アドレスの組を指しているのかを文脈で見分ける必要がある。

## 7.3 Web サーバーのソケット

「Web サーバーのソケット」という特別な種類があるわけではない。nginx や gunicorn などは、設定によって TCP ポートでも Unix ソケットでも待ち受けられる。例えば、nginx がポート 443 で外部からの接続を受け、内部のアプリサーバーとは Unix ソケットでつなぐ構成はよく使われる。

## 7.4 ソケットが持つもの

ソケットは「通信の端点」として、カーネルの中で次のものを持つ。

| 役割 | 内容 |
|---|---|
| アドレス | 自分のアドレス。接続後は相手のアドレスも持つ |
| 送受信バッファ | データの一時置き場 |
| 受付キュー | 待ち受けソケットだけが持つ。`accept()` を待っている接続の列 |
| 状態 | TCP なら LISTEN、ESTABLISHED、TIME_WAIT など。接続がどの段階にあるか |
| 待ちプロセスの管理 | `read()` や `accept()` で眠っているプロセスを記録し、データや接続が届いたら起こす。`select`、`poll`、`epoll`、`kqueue` への通知もここで行う |
| オプション | バッファサイズ（`SO_RCVBUF`）や `TCP_NODELAY` などの設定 |

## 7.5 ストリーム型とデータグラム型

ソケットのバッファを「メッセージキュー」と呼ぶのは、種類によっては正しくない。

- **ストリーム型（`SOCK_STREAM`、TCP など）**：バッファの中身はメッセージの列ではなく、区切りのないバイトの流れである。送る側が `write("ab")` と `write("cd")` を2回呼んでも、受ける側の `read()` には `"abcd"` がまとめて届くことがある。メッセージの区切りはアプリ側で決める必要がある（HTTP ならヘッダの `Content-Length` など）。
- **データグラム型（`SOCK_DGRAM`、UDP など）**：1回の送信が1つのメッセージとして保たれるので、メッセージの列と言える。

また、IPC には「メッセージキュー」という別の仕組み（POSIX の `mq_open` など）がある。ソケットとは別物なので、言葉としても区別しておく。
