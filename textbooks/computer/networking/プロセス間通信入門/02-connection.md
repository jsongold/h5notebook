# 2. 接続の仕組み

## 2.1 待ち受けソケット

待ち受けソケット（listening socket）は、サーバーが接続を受け付けるためにカーネルのメモリ上に作るオブジェクトである。データの送受信はせず、接続の受付だけを担当する。

サーバー側は次の手順で作る。

```c
fd = socket(AF_UNIX, SOCK_STREAM, 0);  // カーネルにソケットを作る
bind(fd, "/var/run/xxx.sock");         // パスと結びつける（ここでファイルができる）
listen(fd, backlog);                   // 待ち受け状態にする（受付キューを持つ）
```

（`bind` の引数は説明のために簡略化している。実際は `struct sockaddr_un` にパスを入れて渡す。）

## 2.2 接続の流れ

1. クライアントがパスを指定して `connect()` すると、カーネルはそのパスから待ち受けソケットを探す。
2. カーネルは接続済みソケットをペアで作り（クライアント用とサーバー用）、それぞれに送受信バッファを用意する。サーバー用のものは、待ち受けソケットの受付キューに並べられる。キューの長さの上限が `backlog` である。
3. サーバーが `accept()` を呼ぶと、キューから1件取り出され、新しい fd として返される。
4. 以降のデータのやり取りは、この新しい fd で行う。待ち受けソケットは次の接続を待ち続ける。

お店にたとえると、待ち受けソケットは受付窓口、`accept()` で返る接続済みソケットは案内された個室である。

## 2.3 listen と経路の確立は別

listen した時点では、受付窓口ができただけで、まだ通信経路はない。経路ができるのは、`connect()` と `accept()` によって接続済みソケットのペアができたときである。

## 2.4 ハンドシェイクとの違い

TCP のハンドシェイク（SYN → SYN/ACK → ACK）は、メッセージをやり取りして接続に合意する手順である。Unix ソケットではパケットのやり取りはなく、カーネルが両者を直接つなぐ。ソケットファイルは、その手順を始めるときに訪ねる住所にあたる。

## 2.5 「ソケットを開く」の意味

- 厳密には、`socket()` を呼んで fd を得ることだけを指す。
- サーバーの文脈では、`bind()` と `listen()` まで済ませて待ち受けている状態を指すことが多い（「ポートを開ける」と同じ使い方）。
- クライアントの文脈では、`connect()` までして相手とつながることを指すことが多い。

誤解を避けたいときは「listen している」「待ち受けている」と言う。

## 2.6 確認方法

- Linux：`ss -xl`
- macOS：`netstat -f unix` や `lsof -U`

どのプロセスがどのパスで待ち受けているかを確認できる。
