# 12. ファイアウォール

## 12.1 家庭用ルーターがスキャンを止める仕組み

家庭用ルーターの多くは、中で Linux が動いている。スキャンの SYN がルーターのグローバル IP に届くと、ルーターのカーネルは、これまでの章と同じようにテーブルを順に引いて処理する。Linux ベースのルーターでは、届いたパケットは先に宛先 NAT（ポートフォワーディングの書き換え）を通り、その後でファイアウォールのルールで判定される。

```
SYN が WAN 側に届く
  ↓
① 宛先 NAT：ポートフォワーディングの行があるか？
     あり → 宛先を中の機器に書き換える
  ↓
② ファイアウォール：既存の接続の続きか？ 許可ルールがあるか？
     中の機器宛て（ポートフォワーディング）で許可あり → 中の機器へ転送（このポートは外から見える）
     外から始まった新しい接続で、許可なし → 捨てる
  ↓ ルーター自身宛てで、許可がある場合
③ ルーター自身の待ち受けソケットテーブル：WAN 側で待ち受けているサービスがあるか？
     なし → 捨てる、または RST を返す
```

どちらにしても、NAT とファイアウォールの両方を通らないと中には入れない。

### ステートフル検査（SPI）

- ルーターは、通過するすべての接続を接続追跡テーブル（Linux では conntrack）に記録している。キーは4つの組（[8章](08-tcp-loopback-and-port.md)）である。
- 中から始まった接続の返事は、テーブルにある接続の続きなので通す。外から突然来た新しい SYN は、テーブルに行がないので捨てる。
- 無差別なスキャンの大半は、ここで止まる。

捨てるのは「外から始まった新しい接続」だけである。中から始めた接続は通るので、普段の通信は普通にできる。例えば PC から Web サイトを見る場合は、次のように流れる。

1. PC が SYN を外に送る。ルーターはこれを通し、接続追跡テーブルに「PC から Web サーバーへの接続」を記録する。
2. Web サーバーから SYN/ACK が返ってくる。テーブルにある接続の続きなので通す。
3. 以降のデータも、同じ接続の続きとして通る。

ルール全体は次のようになる。

| 方向 | 扱い |
|---|---|
| 中 → 外の新しい接続 | 許可（接続追跡テーブルに記録する） |
| 外 → 中で、テーブルにある接続の続き | 許可 |
| 外 → 中の新しい接続 | 捨てる（ポートフォワーディングがあれば例外） |

その結果、家のルーターの後ろからは、外のサーバーに接続することはできても、外から家の PC に接続してもらうことは基本的にできない（それでも通信が成り立つ仕組みは[11章](11-nat.md)）。

### ホワイトリストとの違い

これは「原則として拒否し、許可されたものだけを通す」デフォルト拒否の方式で、考え方はホワイトリストである。ただし、普通のホワイトリストとは2点違う。

- **リストが自動で増えたり減ったりする**：許可の大半は、人が書いたものではない。中から接続を始めるたびに、接続追跡テーブルに行が自動で追加される。接続が終わるか時間切れになると、その行は消える。
- **許可の単位が「接続」である**：「この IP なら常に許可」ではなく、4つの組で決まる1本の接続ごとに許可する。同じ相手からの通信でも、別のポートから来た新しい接続は通さない。

人が書く固定の許可は、ポートフォワーディングだけである。この部分は、普通のホワイトリストに近い。

### ルーター自身のサービス

ルーター自身も、管理画面（Web）などで待ち受けている。正しく設定されたルーターは、これらを LAN 側のインターフェースだけで待ち受ける。`127.0.0.1` と `0.0.0.0` の違い（[10章](10-port-scan.md)）と同じ考え方である。管理画面を WAN 側にも出す「リモート管理」の設定を有効にすると、外から見えるようになる。

### 捨てるか、RST を返すか

| 挙動 | スキャンする側からの見え方 |
|---|---|
| 黙って捨てる | filtered。ルーターがあることや、そのポートの状態が分かりにくくなる。多くのルーターの「ステルスモード」はこの挙動を指す |
| RST を返す | closed。そこに機器がいることは分かる |

実際の初期設定や細かい挙動は、機種によって違う。自分のルーターで確認するには、管理画面のファイアウォール、ポートフォワーディング、UPnP、リモート管理の設定を見るのが確実である。

## 12.2 ファイアウォールの機能

| 機能 | 何をするか | 何の対策か |
|---|---|---|
| パケットフィルタリング | IP アドレス、ポート、プロトコルのルールで、通すか捨てるかを決める | 特定のサービスへのアクセスや、既知の悪い IP からの通信 |
| ステートフル検査 | 接続追跡テーブルで、既存の接続の続きかどうかを見る | 外から始まる接続（スキャン、侵入）。どの接続にも属さない偽のパケット |
| デフォルト拒否 | 許可したもの以外の受信をすべて拒否する | 知らないうちに外に出ているサービス |
| ステルスモード | 拒否したときに RST や ping の応答を返さず、黙って捨てる | 偵察（そこに機器があるかどうかを知られる） |
| アプリ単位の制御 | アプリごとに、受信を許可するか決める | 知らないアプリが勝手にポートを開けること |
| 送信（外向き）の制御 | 中から外への通信も、ルールで制限する | マルウェアが外の指令サーバーへ接続すること、データの持ち出し |
| なりすまし対策 | WAN 側から来たのに送信元が内部の IP になっている、といったパケットを捨てる | 送信元 IP の偽装 |
| 流量制限・SYN 洪水対策 | 同じ相手からの接続の数や速さを制限する | DoS 攻撃、パスワードの総当たり |
| ログ | 拒否したもの、許可したものを記録する | 攻撃の検知、事後の調査 |
| 中身の検査（企業向け製品） | パケットの中身まで見て、攻撃のパターンや危険なサイトを止める | 脆弱性を突く攻撃、危険なサイトへのアクセス |

どこで動くかによって、持っている機能が違う。

| 種類 | 主な機能 |
|---|---|
| 家庭用ルーター | ステートフル検査、デフォルト拒否、NAT が中心。送信の制御はほぼしない |
| macOS 標準のファイアウォール | アプリ単位の受信制御と、ステルスモードが中心。送信は制御しない。送信まで制御したい場合は、LuLu や Little Snitch のような別のツールを使う |
| 企業向けの製品（次世代ファイアウォール、UTM） | 中身の検査、送信の制御、利用者ごとのルールまで持つ |

ステートフル検査とデフォルト拒否は、外から始まる接続を防ぐ機能である。送信の制御は、中から始まる接続の問題に一部対応する機能である。

## 12.3 ファイアウォールはどこに立つか

ファイアウォールは、信頼の度合いが違うネットワークの境界に置く。基本は WAN と LAN の境目である。

**家庭の場合**

```
インターネット(WAN) ── [ルーター：FW + NAT] ── LAN ── PC [ホスト FW]
```

- 家庭では、専用の機器ではなくルーターの中に組み込まれている。ルーターのファイアウォールが、家全体の境界を守る。
- PC のファイアウォール（macOS のファイアウォールなど）が、PC 1台の境界を守る。同じ LAN の中からの攻撃はルーターを通らないので、こちらで防ぐ。

**企業の場合**

```
インターネット ── [境界 FW] ── DMZ（公開する Web サーバーなど）
                                   └── [内部 FW] ── 社内 LAN
```

- 外に公開するサーバーを DMZ という別の区画に置く。公開サーバーが乗っ取られても、社内 LAN の手前でもう一度止められる。
- 社内の部署やサーバー群の間にも、ファイアウォールを置くことがある。

**クラウドの場合**

AWS のセキュリティグループのように、仮想マシン1台1台の手前にファイアウォールがある。境界1か所で守るのではなく、すべての機器が自分の境界を持つ形である。

## 12.4 テーブルの管理だけでは足りない

ファイアウォールルール、接続追跡テーブル、NAT 変換テーブルの管理は大事な要素の1つだが、それだけでは足りない。これらが守るのは「外から始まる接続」だけだからである。

**テーブルの管理で防げること**

外から入れる入口を減らせる。ポートフォワーディング、UPnP、リモート管理を必要なものだけにし、各機器も `127.0.0.1` で済むサービスは外に出さない、といった対策である。攻撃面を小さくするという考え方で、基本中の基本である。

**テーブルの管理では防げないこと**

| 経路 | テーブルで防げない理由 | 主な対策 |
|---|---|---|
| こちらから始める接続（フィッシング、悪意あるダウンロード、ブラウザの脆弱性） | 中から始めた接続は、接続追跡テーブルが自動で許可する | ソフトウェアの更新、怪しいリンクや添付ファイルを開かない |
| 開けている入口の向こう側 | テーブルは通すかどうかを決めるだけで、通した後の安全は守らない | 公開するソフトウェアの更新、認証、設定の見直し |
| 同じ LAN の中（公衆 Wi-Fi、乗っ取られた IoT 機器） | ルーターの内側どうしの通信は、ルーターのテーブルを通らない | PC 自体のファイアウォール、待ち受けるアドレスの制限 |
| アカウントの乗っ取り | 通信の経路の問題ではない | 強いパスワード、多要素認証 |

最近の被害は、中から始めた接続をきっかけにするものが多い。テーブルの管理は入口を減らす土台であり、その上に「ソフトウェアの更新」「認証」「機器ごとの防御」を重ねる多層防御が基本になる。

## 12.5 ファイアウォールなしで強化する

ファイアウォールの役割は、入口が開いていても外から届かないようにすることである。ファイアウォールがない場合は、そもそも入口を開けないこと（待ち受けソケットテーブルに載せない）が一番の対策になる。ここでの「入口」は、ルーターのテーブルではなく、各機器のカーネルの待ち受けソケットテーブル（[9章](09-listening-table.md)）のことである。

| 軸 | 具体的な対策 |
|---|---|
| 入口を作らない | 使わないサービスを止める。必要なサービスも `127.0.0.1` や Unix ソケットで待ち受け、外に出さない。`netstat -an -p tcp \| grep LISTEN` で定期的に確認する |
| 入口を硬くする | ソフトウェアを更新する。サービス自体で認証する（強いパスワード、鍵認証、多要素認証）。TLS で暗号化する。初期パスワードや不要な機能を残さない |
| 被害を小さくする | サービスを root ではなく専用ユーザーで動かす（最小権限）。コンテナやサンドボックスで隔離する。バックアップを取る。ログを見る |
| 中から始まる攻撃 | OS とブラウザを更新する。フィッシングに注意する。インストールするソフトウェアを選ぶ |

## 12.6 送信元 `0.0.0.0/0` のルール

クラウドで「送信元を `0.0.0.0/0` にして許可する」とは、ファイアウォールルールに次の1行が書かれている状態である。

| 方向 | 送信元 | プロトコル・ポート | 動作 |
|---|---|---|---|
| 受信 | `0.0.0.0/0` | TCP 22 | 許可 |

`0.0.0.0/0` は「すべての IP アドレス」を表すので、全世界から 22番への接続を通す、という意味になる（危険性は[10章](10-port-scan.md)）。

外からの SYN が VM のプログラムに届くのは、ファイアウォールルールで許可され、かつ VM のカーネルの待ち受けソケットテーブルに載っている場合だけである。どちらか一方で止まれば、つながらない。

### `0.0.0.0` の2つの意味

`0.0.0.0` は文脈によって意味が違う。

| 書き方 | 意味 | どちら側のアドレスか |
|---|---|---|
| 待ち受けのアドレス（`0.0.0.0:22`） | 自分の持つすべてのネットワークインターフェースで待ち受ける | 自分側 |
| ファイアウォールの送信元（`0.0.0.0/0`） | すべての送信元アドレスを対象にする | 相手側 |

どちらも「全部」を表すが、前者は自分側のアドレス、後者は相手側のアドレスの話である。
