# 3. カーネルとプロセス

## 3.1 カーネルは別プロセスではない

カーネルのコードとメモリは特権を持つ領域にあり、普通のプロセス（ユーザーモード）からは直接触れない。その意味ではプロセスの外にある。

ただし、カーネルは別のプロセスではない。`write()` などのシステムコールを呼ぶと、呼んだスレッド自身がカーネルモードに切り替わり、カーネルのコードを実行する。別のプロセスに処理を依頼するのではない。

イメージとしては、「プロセスの外にいる管理人」よりも「全プロセスに共通する、特権モードでだけ入れる部屋」のほうが近い。

## 3.2 アドレス空間とカーネル

従来、多くの OS ではカーネルのメモリが各プロセスのアドレス空間の上のほうに割り当てられ、ユーザーモードからのアクセスだけが禁止されていた。

Meltdown 脆弱性への対策（Linux の KPTI など）以降は、ユーザーモードで動いている間はカーネルのメモリの大部分がアドレス空間から外され、システムコールでカーネルモードに入ったときに切り替えて見えるようにする方式が多い。

## 3.3 データの2回コピー

Unix ソケットでデータを送ると、2回コピーされる。

```
送信プロセスのメモリ --(1) write--> カーネル --(2) read--> 受信プロセスのメモリ
```

1. `write()`：送信側のユーザー空間のバッファから、カーネルのメモリへコピーする。Linux では、このデータはそのまま受信側ソケットの受信キューにつながれる。
2. `read()`：カーネルのメモリから、受信側のユーザー空間のバッファへコピーする。

カーネルを経由するのは、プロセス同士がお互いのメモリを直接見られないように分離されているからだ。カーネルが間に入ってコピーすることで、安全に受け渡す。

## 3.4 カーネルメモリは「共有メモリ」か

カーネルのメモリは物理的に1つで、全プロセスから共通で参照される。その意味では共有されている。

しかし、IPC でいう「共有メモリ」とは別物である。

| | IPC の共有メモリ | カーネルメモリ |
|---|---|---|
| ユーザーモードから直接読み書き | できる | できない |
| データの受け渡し | 普通の変数として読み書き | システムコールでカーネルにコピーしてもらう |

カーネルメモリにユーザーモードから触れないことが、3.3 の2回コピーが必要な理由である。
