## 2. What do the hooks do (events, side effects, network, telemetry)?

### Takeaway
hooks/hooks.json defines 24 hook entries across PreToolUse, PostToolUse, PostToolUseFailure, PreCompact, SessionStart, Stop, SessionEnd, all routed through profile gating (`ECC_HOOK_PROFILE` minimal/standard/strict, `ECC_DISABLED_HOOKS`). Side effects are mostly local file writes under ~/.claude and project dirs; I found no hook that posts telemetry to a remote ECC service, but the pre-compact/session summary hook shells out to `claude -p` (a model call via the user's own Claude Code), and MCP health checks make HTTP probes to configured MCP servers.

### Cited Findings
- Event/matcher list (from hooks.json, ids in hooks.metadata.json) — [hooks/hooks.json](https://github.com/affaan-m/ECC/blob/main/hooks/hooks.json), [hooks/hooks.metadata.json](https://github.com/affaan-m/ECC/blob/main/hooks/hooks.metadata.json):

  - PreCompact: pre-compact. SessionStart: session-start bootstrap; plan-canvas-sessions.
  - PostToolUse: two dispatchers (sync and async) bundling quality gate, design-quality-check, post-edit format/typecheck/console warn, PR-created logger, build-complete analysis, session-activity-tracker, observe.
  - PostToolUseFailure: mcp-health-check (mark unhealthy + reconnect attempt), skill-run-tracker.
  - Stop: plan-canvas-pending, stop-format-typecheck (300 s timeout, batch), check-console-log, session-end, evaluate-session, cost-tracker, desktop-notify (last 4 async).

## 3. Notable design ideas

### Takeaway
Instinct-based continuous learning (v2.1), hook-enforced guardrails (GateGuard, config-protection), local memory persistence across sessions/compactions, explicit token/cost controls, verification loops, and multi-agent/multi-model orchestration patterns (GAN trio, santa loop, council, worktree orchestration, ECC2 control plane).

### Cited Findings
- Continuous learning v2.1: hooks capture tool use into observations.jsonl (per project hash); a background observer agent (Haiku) detects user corrections, error resolutions, repeated workflows and writes atomic "instincts" (YAML: id, trigger, confidence 0.3-0.9, domain, scope project/global, evidence). Project-scoped by git remote/repo path; promoted to global when seen in 2+ projects; `/evolve` clusters instincts into skills/commands/agents; `/instinct-status|export|import`, `/promote`, `/projects`, `/prune`. v1 was a Stop-hook evaluator (still present as evaluate-session). Env `ECC_INSTINCT_CONFIDENCE_THRESHOLD`, `ECC_MAX_INJECTED_INSTINCTS` — [skills/continuous-learning-v2/SKILL.md](https://github.com/affaan-m/ECC/blob/main/skills/continuous-learning-v2/SKILL.md), [docs/continuous-learning-v2-spec.md](https://github.com/affaan-m/ECC/blob/main/docs/continuous-learning-v2-spec.md)
- Memory persistence: session-start loads bounded prior context; pre-compact stores an LLM summary; session-end updates session file each Stop; commands `/save-session`, `/resume-session`, `/sessions`; also memory MCP configs (ecc-memory-vault, memory, omega-memory, longhand, memxus) and scripts/memory-mcp.mjs — [hooks/memory-persistence/README.md](https://github.com/affaan-m/ECC/blob/main/hooks/memory-persistence/README.md), [mcp-configs/mcp-servers.json](https://github.com/affaan-m/ECC/blob/main/mcp-configs/mcp-servers.json)
- Token optimization: docs recommend `model: sonnet`, `MAX_THINKING_TOKENS=10000` (default stated 31,999), `CLAUDE_CODE_SUBAGENT_MODEL=haiku`; model-selection table (Haiku exploration, Sonnet daily, Opus architecture); strategic-compact skill/hook suggests manual `/compact` about every 50 tool calls at logical phase boundaries rather than auto-compact; skills: context-budget, token-budget-advisor (25/50/75/100% depth choice), cost-aware-llm-pipeline; `/model-route`, `/cost-report`; MCP token-optimizer server entry; `ECC_CONTEXT_MONITOR_COST_WARNINGS` — [docs/token-optimization.md](https://github.com/affaan-m/ECC/blob/main/docs/token-optimization.md), [skills/token-budget-advisor/SKILL.md](https://github.com/affaan-m/ECC/blob/main/skills/token-budget-advisor/SKILL.md), [scripts/hooks/suggest-compact.js](https://github.com/affaan-m/ECC/blob/main/scripts/hooks/suggest-compact.js)

## 5. Component dependency graph, coupling, size, and AI-maintainability (added on coordinator request)

Method: scripted regex analysis over the same checkout (HEAD c70874f). Counts are my own measurements; regex-based so approximate.

### Takeaway
Explicit declarations exist only at the packaging layer (install-modules.json with 38 modules and dependencies, 85 install components, 7 profiles, hooks.metadata.json sidecar, a generated COMMAND-REGISTRY.json). The command -> agent -> skill relationships are mostly implicit prose, partly mirrored in a generated registry that undercounts them. Hooks are coupled to scripts and each other through env vars and shared state files under ~/.claude. The repo does ship a strong validation suite and AGENTS.md/CLAUDE.md, so an AI can change it with guardrails, but the size (about 4,200 files) means it must navigate via the registries and CI validators rather than read everything.

### Cited Findings
- Explicit, machine-readable declarations:
  - manifests/install-modules.json: 38 modules, each with id, kind, paths, targets (harnesses), `dependencies` (module ids), defaultInstall, cost, stability. Example: `framework-language` depends on rules-core, agents-core, commands-core, platform-configs; `workflow-quality` depends on `skill-unified-memory`; `optimization-workflows` depends on workflow-quality and operator-workflows. Every one of the 293 skills is listed by path in modules (module-level, not per-skill dependency) — [manifests/install-modules.json](https://github.com/affaan-m/ECC/blob/main/manifests/install-modules.json). install-components.json has 85 components; install-profiles.json has 7 profiles — [manifests/](https://github.com/affaan-m/ECC/tree/main/manifests).
  - hooks/hooks.metadata.json is a sidecar keyed by event/index with id, description, fingerprint (matcher + command hash); `validate-hooks.js` fails on drift — [hooks/README.md](https://github.com/affaan-m/ECC/blob/main/hooks/README.md).
  - docs/COMMAND-REGISTRY.json (generated by scripts/ci/generate-command-registry.js; `command-registry:check` in npm test): per command description, type, primaryAgents, allAgents, skills, path. Of 94 commands, only 17 list agents and 40 list skills — [docs/COMMAND-REGISTRY.json](https://github.com/affaan-m/ECC/blob/main/docs/COMMAND-REGISTRY.json). ### Inferences
- To add a skill safely an agent needs: SKILL.md with frontmatter, an entry in the relevant install module path list, regeneration of catalog/registry counts, and passing validate-skills; these steps are enforced by CI failures rather than a single how-to in CLAUDE.md (the SKILL-DEVELOPMENT-GUIDE at 920 lines is the how-to). Trial-and-error against `npm test` is the practical workflow.
- Editing a hook (e.g., changing hooks.json) requires edits in the metadata sidecar and fingerprints, else CI fails; the big hook scripts (gateguard 1,960 lines, install-lifecycle 2,549) are hard to modify without reading in full.
- Claude Code cannot infer the full command -> agent -> skill graph from frontmatter; it needs COMMAND-REGISTRY.json (incomplete: 17/94 with agents versus 36 by my prose scan) plus grep. Cross-skill refs are sparse (26/293), so most skills are independent and can be edited in isolation; coupling concentrates in hooks/scripts/state files and the install manifests.
